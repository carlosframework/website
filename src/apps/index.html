What kinds of apps can you build on CARLOS?

From a personal utility to a shared workspace or social network, you choose how to arrange your app. An instance is one running copy: use one, or give each person, team or project their own. Decentralisation is optional.

Personal apps

Notes, files and fitness apps could use one instance per person. Kass is an example of this design.

Team workspaces

Documents, calendars and shared inboxes could use one instance per team. Oficina is an office suite with data sealed per team.

Developer tools

Git hosting, continuous integration (CI) and project tools could use one instance per project or repository. amadan combines Git hosting and CI.

Connected communities

Social networks and messaging apps could use separate instances that communicate through app-defined protocols. You build those connections into the app. Woodstar is an example of a social app that supports ActivityPub and AT Protocol.

Business applications

Ticketing, customer relationship management (CRM), internal tools and one-off apps can use one centralised instance. They could also use separate instances for separate customers. Tito is an example of a business adopting CARLOS.

Small utilities

Reporting, scheduled jobs and integrations can run as a self-contained process that does one job. Cribado handles email authentication reports.
