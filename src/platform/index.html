CARLOS platform

CARLOS platform is an open-source, web application deployment platform for single-process web apps. CARLOS runs on your own infrastructure or via a PaaS provider, like Carloku.

Multi-region, multi-host out of the box

CARLOS runs single-tenant, full-stack web applications as self-contained processes. This means deploying to hosts running on any provider or network, anywhere on the world becomes as simple as copying files.

Single-tenant apps

The first step of building a CARLOS app is choosing the tenant boundary. A tenant can be a team, a profile, a repo etc. Tenants can run independently, alongside centralised "glue" infrastructure, or as part of a set of interdependent services.

Releases and automation

You can deploy through the command-line interface (CLI) or application programming interface (API). People or agents can drive deployments, with zero-downtime swaps, release channels, rollback, logs and scheduled jobs available through the platform.

Hibernation built in

Hibernating apps mean that instances not in use don't use any compute or memory. Typical apps flash back to life in an imperceptible <500ms, and continuously streamed data is always backed up, always current.

Shipping

  • Release channels: Move versions through named channels.
  • Fast deploys: Apply release changes quickly.
  • Staggered fleet rollouts: Update groups of machines in stages.
  • Production canary releases: Test releases on separate production URLs.
  • Rollback: Return an application to its previous release.
  • Pipeline bake windows and sign-offs: Require a waiting period or approval before a release advances.

Running

  • High availability: Keep apps available when a host fails.
  • Zero-downtime updates: Update applications without planned downtime.
  • Regional moves: Move an application between regions.
  • Multi-region placement: Run an application in more than one region.
  • Multi-provider and self-hosted fleets: Use multiple providers or self-hosted fleets.
  • Hibernation: Sleep services and wake them when requests arrive.

App services

  • Email sending: Send email through a configured backend, with verified domains and delivery events.
  • Custom domains: Attach your own hostnames to applications.
  • Automatic TLS certificates: Issue certificates automatically for custom domains.
  • Object storage: Use a configured backend after operator approval.
  • Scheduled jobs: Call an application path on a schedule.
  • Environment configuration and secrets: Set runtime configuration and protected values.

Operating

  • CLI and API automation: Manage apps from scripts, agents or your terminal.
  • Unified logs: Collect application and platform logs in one place.
  • Grouped errors: Group errors from app logs and HTTP 5xx responses.
  • Optional edge analytics: Count visits without cookies when enabled.
  • Feature flags: Change app-defined settings without a new release.
  • Scoped service credentials: Limit automation credentials to named permissions.
