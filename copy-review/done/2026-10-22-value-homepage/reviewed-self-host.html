CARLOS

Self-host CARLOS platform

A CARLOS platform deployment needs its own console, object-store bucket, hosts running carlos, and domain name system (DNS) records. You operate the deployment service for your apps, including routing and host services.

Choose your host and services

Choose the compute location and service providers separately. Linux hosts provide the full service path through systemd, the Linux service manager.

On Amazon Web Services (AWS), the existing integrations use S3 for storage, IAM for managed app-storage credentials, SES for email, and Route 53 for latency-based DNS.

You can run hosts outside AWS and still use AWS services. CARLOS_S3_ENDPOINT points platform storage at an S3-compatible endpoint. That changes the storage endpoint, but the AWS provisioner still uses AWS IAM. Managed email and latency-based DNS also retain their AWS integrations.

For a deployment without AWS, validate the object store’s conditional writes and choose which integrations to provide. S3 compatibility alone does not supply an alternative to IAM, SES or Route 53.

Set up the deployment

Choose the host, bucket, and domain first. Install carlos on the hosts, then bootstrap them and configure the bucket access, release verification, console identity and domain, and host services. Configure DNS and encrypted HTTPS.

This guide outlines the deployment choices. Use the CLI documentation for operator command reference. Host setup and configuration are defined in the CARLOS platform repository.

Point the CLI at your own console. Deploy a first app, verify its route, and test recovery. Add optional email or latency-based DNS integrations only after the base deployment works.

Operate it

The operator maintains the hosts, applies updates, checks storage and backups, and verifies recovery. Keep those checks independent of the provider you choose.
